# Review rules: nixos-config

- Add every new module file to the `default.nix` aggregator in its folder. Build it on the pattern `options.modules.<ns>.<name>.enable = mkEnableOption ...` plus `config = mkIf cfg.enable { ... }`.
- Give every new `.age` file an entry in `secrets/secrets.nix`, using the narrowest key list that works. Home Manager secrets use `home-keys` only.
- Do not hardcode the user name, the home directory or the host name in a module. Use the `username`/`hostname` specialArgs or the host `variables.nix`.
- When you bump a pinned source version, change its hashes and its source `name` (for example `trivy-${version}-source`) in the same change. Nix otherwise reuses the old cached source without an error.
- Do not link a file that a program writes to through the Nix store (`home.file`, `mkOutOfStoreSymlink`). The write fails with `EROFS`.
- Every temporary overlay or patch must have a comment that says when to remove it.
- Do not reformat code that the change does not touch. Keep hand-aligned comments, for example in `home.packages`.
- A PR that changes the tech stack, architecture, domain entities or constraints updates `docs/project.md`.
